# 资产发布流程

## 存储分工

GitHub 存放介绍、预览图、公开清单和下载链接。R2 存放模型、Blender 工程、缓存、视频与代码压缩包。日常工作文件保留在原项目，不为发布移动或覆盖原件。

建议一个专用 R2 桶，仅存明确要公开的内容。正式下载优先绑定自有域名；`r2.dev` 是有速率限制的开发访问方式，不作为长期正式分发的默认方案。[Cloudflare 官方说明](https://developers.cloudflare.com/r2/buckets/public-buckets/)

R2 并非无限免费，存储和操作可能收费；出站流量计费规则、免费额度以[官方价格页](https://developers.cloudflare.com/r2/pricing/)为准。当前未建立桶，也未产生本仓库的 R2 上传。

## 每次新增资产

1. **确定范围**：资产名称、稳定 ID、版本、用途、第三方依赖和授权；不默认发布整个项目。
2. **准备发布副本**：清除凭证、私人路径、无关文本块和录制文件。Blender 贴图打包或改为相对路径；缓存一起带上。
3. **重开验证**：从独立目录打开发布副本，验证贴图、缓存和动画；导出格式没有验证过就不写“支持”。
4. **打包**：模型包、完整工程包、代码包按需拆开；只制作有实际内容的下载项。记录准确字节数与 SHA-256。
5. **上传 R2**：对象键 `assets/<asset-id>/<version>/<filename>`。使用新版本，不覆盖旧链接。设置正确 Content-Type，版本化文件可设置长期缓存。
6. **验证公开下载**：通过公开 HTTPS 链接完整下载到临时目录，比较大小和 SHA-256。仅 HEAD 成功不足以证明文件完好。失败时保留 preview 状态。
7. **更新目录**：填写 manifest.json 下载项，再更新详情页和 catalog.json；验证三处版本、状态、链接一致。
8. **发布 Git**：只提交已审查的文档、图片和清单。暂未接通的链接留空，不发布带占位域名的下载按钮。

## 下载项字段

每条下载记录包含 `label`、`filename`、`url`、`bytes`、`sha256`、`content_type`。`url` 必须是公开 HTTPS 链接，不带短期签名查询参数。

## R2 配置要求

常规上传只需要限定到专用桶的对象读写权限。创建桶、绑定域名和 DNS 属于初始化管理步骤，不应让日常发布凭证长期拥有整个账户的管理权限。

本地配置放在仓库之外，或放入已忽略的 `.env`：

- `R2_ACCOUNT_ID`
- `R2_ACCESS_KEY_ID`
- `R2_SECRET_ACCESS_KEY`
- `R2_BUCKET`
- `R2_PUBLIC_BASE_URL`

不要把这些配置的真实值放进文档、提交历史或截图。S3 接口地址是上传端点，不是公开下载域名。

## 回滚

旧版本文件保持不动。新版本有问题时，在目录里撤下该下载项并标明原因，不悄悄替换相同 URL 下的内容。删除远端历史资产需要另行确认，不在自动发布中执行删除。
